# Pinned, and pinned in this file rather than in a separate lock.
#
# Two reasons. The image is then byte-identical between builds. And Trivy's pip
# analyzer matches on the filename `requirements.txt`: a `requirements.lock`
# beside a range-based requirements.txt is silently not scanned, and the gate
# reports "no findings" because it found nothing to look at, which reads exactly
# like a clean scan. That is the supply-chain lesson from cube-store restated in
# a different shape: a passing scanner is a claim about the scanner until
# something has been shown to fail.
#
# Regenerate with:
#   uv pip compile requirements.in --python-platform x86_64-unknown-linux-gnu \
#     --python-version 3.12 --output-file requirements.txt
#
# pandas is deliberately absent. Nothing here uses it, and a dependency that is
# only in the file is still in the image, still in the CVE feed, and still a
# thing to explain.
